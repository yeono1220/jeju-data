1. 문제 정의

탐나는전 적립(캐시백)은 한 해 예산이 정해져 있는데, 적립률을 높게 시작하면 한 해 중간에 멈춥니다. 2026년에는 예산 425억 원 중 154억 원이 20% 적립한 2월 한 달에 쓰여 7월 13일 적립이 중단됐고(제이누리, 2026.7.13), 2022년 4월·2023년 5월·9월에도 같은 일이 있었습니다. 소진일을 맞히려면 "적립률을 1%p 올리면 사용이 얼마나 느나"를 알아야 하는데, 도 발표로도 7→10% 때 +21.6%, 7→14% 때 +39.2%(한라일보, 2025.3.12)로 잴 때마다 다릅니다. 15%·월 200만 원 한도 때는 학원비를 몇 달치 미리 낸 사례가 보도됐고 학원·교육 비중이 13.3%에서 18.2%로 올랐습니다(중앙SUNDAY, 2025.7.26). 이런 앞당긴 소비를 반응으로 착각하면 근거가 틀어지고, 혜택은 사교육비를 많이 쓰는 가구로 쏠립니다(역진성). 탐나는전 결제 데이터(1-32)는 제주빅데이터센터 안에서만 볼 수 있어 비전공자가 이 계산을 하기 어렵습니다.

데이터올레는 질문 한 줄로 진단 → 효과 추정(반응도·앞당긴 소비·백테스트) → 설계(같은 예산 A~E안) → 실행물 → 효과 확인을 잇는 AI 에이전트입니다.

5. 검증

  • 심어 둔 정답 복원: 가상데이터에 반응 log 0.045/%p(+4.6%)와 학원 선결제를 심고, 분석이 +4.8%(구간 안)와 '학원만 앞당긴 소비'를 찾는지 자동 테스트.
  • 백테스트: 추정에 쓰지 않은 달의 예측 오차가 흔한 방식보다 작은지 자동 테스트.
  • 레벨 0 누수: 가짜 Claude로 에이전트를 돌려 밖으로 나간 모든 내용에 동네·시장·업종·요일 이름, 추천 이유, 단위 붙은 수치가 0건인지, 돌아온 답이 원래 말로 채워지는지 자동 테스트.
  • 반출 검수 역산 공격, 예산·소진일 손계산 대조, 실행물 문구 숫자 검사, 질문 계획 50문항 100% — 자동 테스트 108개 통과.

6. 한계

  • 시연 수치는 가상데이터입니다. 실데이터에서는 반응을 매번 자료에서 추정하고, 추정할 수 없으면 그렇다고 밝힙니다.
  • 적립률 이력은 2024년 1월 이후를 보도 원문으로 확인했습니다. 2023년(현장 할인)은 추정에서 빼고, 달 안에서 적립이 멈춘 구간(2024년 12월 12~22일, 제주도 보도자료)은 '가정'으로 표시합니다(공식 이력으로 교체 가능).
  • 누가 썼는지(소득·나이)와 1인 월 한도 효과는 자료에 없어 업종·동네 대리지표로 봅니다.
  • 최종 반출은 센터 심사가 결정하며, 배분안·실행물은 담당 부서가 확정 전 검토하는 초안입니다.

7. 센터 활용 방안

도·행정시 지역화폐 담당이 예산 편성 전 데이터 프리존을 방문해 질문 한 줄로 배분안과 개선안 초안을 받아 가고, 시행 12주 뒤 효과 확인 질문으로 다시 방문하는 순환을 만듭니다. 주민센터·상인회는 동네 진단 카드와 안내문을, 연구자는 반응도·이중차분 결과를 논문 문단으로 받습니다. AI가 막힌 환경에서도 규칙 기반으로 같은 결과가 나오므로 센터 보안 정책과 충돌하지 않습니다.
